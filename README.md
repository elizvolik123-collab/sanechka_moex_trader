# MOEX Trader

Дневник сделок на Московской бирже, калькулятор позиции и лента новостей. Для локального запуска внешние API-ключи не требуются. При штатном запуске команда `setup:local` создаёт секреты приложения и пароль локальной базы.

## Просмотр интерфейса без API

После установки зависимостей выполните `corepack pnpm run preview:visual` и откройте
[MOEX Trader](http://127.0.0.1:3000). PostgreSQL, ключи и воркер не нужны.
Калькулятор использует учебные параметры SBER, лента содержит пример новости,
а дневник и списки в кабинете показывают пустые состояния. API и отправка форм отключены.

## Первый запуск

Установите Node.js 24 LTS. Распакуйте ZIP, откройте терминал в папке `moex-trader` и выполните:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm setup:local
corepack pnpm db:start
```

Оставьте окно с PostgreSQL открытым. Во втором терминале в той же папке:

```sh
corepack pnpm db:deploy
corepack pnpm db:seed:dev
corepack pnpm dev
```

Откройте **http://127.0.0.1:3000** и зарегистрируйтесь. Без токенов доступны калькулятор и импорт сделок (например, [тестовый CSV](docs/samples/import-sample.csv)). Справочник `db:seed:dev` учебный; актуальные параметры загружает команда `corepack pnpm moex:sync`. В следующих запусках достаточно `db:start` и `dev`; миграции повторяйте после обновлений.

Для синхронизации брокера, обновления справочника и сбора новостей запустите в третьем терминале `corepack pnpm worker`. Для остановки процессов нажмите Ctrl+C в их окнах. Готовность приложения и базы: http://127.0.0.1:3000/api/health.

## Подключение Т‑Инвестиций и локальные настройки

| Что | Где задать |
| --- | --- |
| Токен Т‑Инвестиций | Нужен для синхронизации с брокером. Создайте токен «Только для чтения», вручную вставьте его в **Кабинет → Брокеры → API-токен** и запустите воркер. Импорт CSV/XLSX доступен без токена. |
| Секрет сессий, ключ шифрования брокерских токенов, пароль локальной БД | `setup:local` создаёт их в личном `.env`. Повторный запуск сохраняет существующий файл. |
| SMTP и прокси | При необходимости задайте свои `SMTP_URL` / `MAIL_FROM` или `HTTPS_PROXY` / `NODE_USE_ENV_PROXY=1` в `.env` по [.env.example](.env.example). |
| MOEX ISS и лента Telegram | Используют публичные источники. API-ключ и токен Telegram-бота не нужны. |

Не пересылайте `.env`, папку `.data` и брокерские отчёты. Сохраните `TOKEN_ENCRYPTION_KEYS` отдельно от копии рабочей базы: прежние токены требуют прежнего ключа. В локальном режиме без SMTP тестовые письма для сброса пароля доступны в `.data/mail`.

Для теста брокера без реального токена добавьте в `.env` свои `MOCK_TINVEST_TOKEN` (формат `t.mock-` плюс минимум 13 букв, цифр или дефисов), `TINVEST_API_URL=http://127.0.0.1:4010/rest` и `TINVEST_LOGO_CDN_URL=http://127.0.0.1:4010/logos`. Запустите `corepack pnpm tinvest:mock`, перезапустите web и worker и введите **вымышленный** токен в форму брокера.

## Разработка и сервер

- Инструкции для GPT и других агентов: [AGENTS.md](AGENTS.md). Архитектура и границы функциональности: [docs/architecture.md](docs/architecture.md).
- Проверки: `corepack pnpm test`, `corepack pnpm typecheck`, `corepack pnpm lint`, `corepack pnpm build`.
- Развёртывание: скопируйте [.env.example](.env.example) в `.env`. Укажите `DOMAIN`, публичный `BETTER_AUTH_URL`, новый `POSTGRES_PASSWORD`, новый `BETTER_AUTH_SECRET` и `TOKEN_ENCRYPTION_KEYS`. Для генерации 32 случайных байтов используйте `openssl rand -base64 32`; для ключа шифрования добавьте префикс `1:`. Для пароля PostgreSQL удобно использовать `openssl rand -hex 24`. Для восстановления пароля добавьте настройки SMTP. Запустите `docker compose up -d --build` на сервере с Docker, DNS-записью и открытыми портами 80 и 443. Compose применяет миграции до старта приложения, Caddy обслуживает HTTPS.
- Если публичные источники недоступны из вашей сети, настройте доступ к ним через свой прокси. Для проверки интерфейса используйте учебный справочник и тестовый CSV.
- Резервная копия PostgreSQL на сервере: `sh deploy/backup.sh`. При ротации добавьте новый ключ к старым и обновите `TOKEN_ENCRYPTION_KEY_VERSION` перед перезапуском.
